## The system (4 repos, one product: "EduManage" school management)
| Repo | What | Stack |
|---|---|---|
| `shelfwatch_sfa_ir_backend` (this) | REST API | FastAPI 0.115, PyMySQL (raw SQL), MySQL 8 / TiDB, Alembic |
| `shelfwatch-plus` | Admin/staff web app (one school) | Vite + React 18 + react-router 6 + Tailwind 3 |

Names say "shelfwatch" but it is a school app, not retail. **Multi-school**: one API serves many schools ("organisations").

## Organisations (multi-school) — read before touching SQL (`docs/ORGANISATIONS.md`)
- `organisations` (id, code, name, is_active). Login/forgot/verify/reset take `org_code`; missing → `DEFAULT_ORG_CODE` (default `DEFAULT` = the pre-0009 school, org id 1). Usernames unique **per school**.
- 30 per-school tables carry `org_id INT NOT NULL` (**no default** — an INSERT without it errors): users, classes, sections, teacher_assignments, student_profiles, attendance, fees, fee_claims, transactions, lesson_plans, notices, enquiries, exams, timetable_slots, calendar_events, holidays, leave_requests, salary_records, staff_attendance, vehicles, sms_messages, school_timings (1 row/school), substitution_requests, class_homework, audit_logs (nullable) + (0011) announcements, school_documents, messages, events, student_transport + (0012) transport_shifts + (0018) class_announcements. Child tables reached via a validated parent have none (announcement_images, message_recipients, event_media, transport_shift_students, notice_classes, class_announcement_sections).
- Unique keys are per school (`uq_users_org_username`, `uq_classes_org_name`, `uq_holidays_org_date`, `uq_vehicles_org_vehicle_no`, `uq_calendar_events_org_title`, `uq_student_org_admission_no`, `uq_users_org_principal`, `uq_school_timings_org`).
- `get_current_user` → `auth.authenticate` binds the request `Db` to the user's school: **services use `db.org`** (raises if unbound). Rule: every query/insert on a per-school table has `org_id = %s`; every client-supplied id is looked up with the org filter first.
- JWT has `org` claim; disabled school → 403 login, 401 tokens/refresh. Throttle keys `"<org_id>:<username>"`; reset emails use the school name.
- New schools: `python -m app.cli create-org CODE "Name"` or `POST /platform/organisations` (`X-Platform-Secret: $PLATFORM_SECRET`; 404 when unset). Public `GET /organisations/{code}` → `{code,name}` for login screens.

## Platform API (owner portal `work/dashboard`) — `routes/platform.py` + `services/platform.py`
- Guard `dependencies.platform_operator`: `X-Platform-Secret` (hmac compare; 404 if PLATFORM_SECRET unset, 403 if wrong); returns `X-Platform-Actor` (operator email, regex-checked) → stored as `details.operator` in audit entries.
- Cross-school code **does not use `db.org`**: it filters/groups by `org_id` explicitly; one-school actions `db.bind_org(org_id)` first. Every cross-school number = a fixed number of `GROUP BY org_id` queries (never one query per school).
- `/platform/overview` (totals + 14-day trends + rows) · `/platform/organisations` GET rows (counts, `attendance_today`, `attendance_14d`, fees, pending, `active_users` from `auth_sessions.last_used_at` (UTC), `alerts`) / POST create · `/platform/organisations/{code}` GET detail / PATCH · `/{code}/users` (paged, `X-Total-Count`) · `/{code}/users/{id}/password` · `/{code}/users/{id}/sign-out` · `/platform/activity` (audit log, `before_id` cursor, action prefix) · `/platform/system`.
- Times: TIMESTAMP columns come back in school time, auth tables are naive UTC → responses are ISO strings with offset (`_school_iso` / `_utc_iso`). Sign-in counts per school use throttle keys `"<org_id>:%"`.
- Alert codes: disabled, setup_incomplete, inactive_30d, inactive_7d, attendance_not_marked (Mon–Sat, not a holiday), fees_overdue, fee_claims_waiting.

## Layout & rules
- `app/main.py` app factory; `routes/__init__.py` ALL_ROUTERS
- `routes/` HTTP only (parse, role check, call service) — **no SQL in routes**
- `services/` business rules + SQL; raise `app.core.errors` (→ `{"detail": ...}`), never touch HTTP objects
- `models/` Pydantic request models per domain; `db/` pool + request-scoped transactional session
- `core/` config, security (Argon2id, JWT, rotating refresh tokens), signed file URLs, clock (Asia/Kolkata), logging/Sentry
- `storage/` local or S3 (R2/OCI); `mail/` SMTP or console; `services/user_import/` Excel (.xlsx, CSV still read) + photo-ZIP bulk import; `services/spreadsheet.py` shared .xlsx read/write

- SQLAlchemy used **only** by Alembic. Migrations: `migrations/versions/0001…0018` (`0010_platform_indexes`, `0011_student_portal`, `0012_driver_routine`, `0013_keep_history`, `0014_login_captcha`, `0015_exam_subject_marks`, `0016_durable_jobs`, `0017_protect_records` (see "Review fixes"), latest `0018_class_notices` (see "Class notices"); table in `docs/OPERATIONS.md`); `legacy/` = old SQL v3–v8. - `scripts/seed_driver_routine.py` — dev demo data for the driver app: `python -m scripts.seed_driver_routine [--org DEFAULT] [--driver driver] [--vehicle "DEMO VAN 1"]` (needs students in the school; rebuilds the same demo when run again)

## Review fixes (late Oct 2026, migrations 0013–0017) — `tests/test_review_fixes.py`, `tests/test_protect_records.py`
- **Nobody is hard-deleted** (`services/leaving.py`): `DELETE /users/{id}` / `DELETE /students/{id}` (`?reason=`) = `mark_left` → `is_active=0`, `left_on`, `left_reason`, sessions/devices/reset codes gone, student detached from class/section (kept in `last_class_id/last_section_id`) and transport, teacher's assignments/timetable slots/vehicle driver removed, open substitutions closed, pending leaves cancelled, audited; all records kept. `POST …/reactivate` (`needs_class` / `roll_no_cleared` when the old section/roll is gone). Lists `?status=active|left|all` (default active); `GET /students?q=` searches name/username/admission/roll. Only MANAGERS mark students left (class teachers can't). Left accounts keep their username / admission number reserved. FKs to users: authors `SET NULL`, owners `RESTRICT` (0013) — a raw DELETE fails instead of wiping history. Queries joining an author use LEFT JOIN. Login of a left account → 403 "…marked as left the school…".
- **Sign-in throttling** (`services/login_throttle.py`, `services/captcha.py`, 0014): counted per account, account+device (`X-Device-Id` header → `core/context.device_id()`), and address. Clients sending `captcha_supported: true` get `428 {code: captcha_required|captcha_invalid}` after 3 account / 20 address failures, `POST /auth/captcha` → PNG data URL (Pillow), one try per picture, stored as HMAC; per-device lock after 5; address flood limit 500. Old clients keep 50/address. Details `docs/AUTH.md`.
- **Input checks**: attendance for a future date → 400; exam marks 0 ≤ marks < 10000 and ≤ `max_marks` (exam or result); results per subject (`exam_results.subject`, `''` = whole exam; 0015); `/student/exams` adds `subjects`, `total`, `max_total` (and fills `marks` from the total for old apps). Session attendance % counts elapsed working days only (+ today once marked; `working_days_total`, `is_future`).
- **Records are never erased by deleting a class / section / exam / fee** (27 Oct 2026, migration 0017, `tests/test_protect_records.py`): `DELETE /classes/{id}/sections/{sid}` is refused (409 `{detail, code: "has_records", records: {attendance, homework, documents, substitutions}}`) while the section has attendance, class homework, timetable/syllabus documents or substitution records; `DELETE /classes/{id}` the same for all its sections + its lesson plans and exams that have results (`exams_with_results`); `DELETE /exams/{id}` while any result exists (`students_with_results`; advice: unpublish instead); `DELETE /fees/{id}` when the fee is paid or has a pending/approved payment proof (rejected proofs are deleted with it, as before).
